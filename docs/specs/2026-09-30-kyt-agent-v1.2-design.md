# KYT Agent v1.2 設計文件：可信度與可觀測性

- 日期：2026-09-30
- 狀態：已實作
- 前一版：[2026-09-29-kyt-agent-v1.1-design.md](2026-09-29-kyt-agent-v1.1-design.md)

## 1. 背景

v1.1 eval（28 筆）召回率 100%、誤報率 8%，唯一誤報為 Tornado Cash relayer 下游案例。v1.2 不改架構，補強四個面向：

| 面向 | 問題 | 對應章節 |
| ---- | ---- | -------- |
| 判斷正確性 | 無法區分 relayer 手續費收入與洗錢中間人 | §2 |
| 安全 | 鏈上字串（代幣 symbol、合約名稱、ENS）由第三方控制，會直接進入 LLM | §3 |
| 可信度 | LLM 非確定性，單次 eval 無法說明判斷是否穩定 | §4 |
| 可觀測性 | 無法確認 prompt caching 是否生效；LangSmith trace 無法對應案件；部分失敗未留下 audit | §5、§6 |

## 2. Relayer 辨識

### 2.1 資料

- 新增標籤分類 `relayer`，嚴重度介於 `exchange` 與 `bridge` 之間；同一地址有多個標籤時仍保留最嚴重者
- `data/labels/relayers.csv`：取自 Tornado.Cash Relayer Registry（`0x58e8dcc13be9780fc42e8723d8ead4cf46943df2`，Etherscan 名稱標籤「Tornado.Cash: Relayer Registry」）的 `RelayerRegistered` 事件，去重後 123 個地址
- 名稱一律為「Tornado Cash relayer」，`source` 只記錄登記交易 hash；不收錄 ENS 原文（見 §3）

### 2.2 判斷規則

- `relayer` 不屬於 `HIGH_RISK_CATEGORIES`，規則層下限不受影響
- prompt：relayer 的混幣器轉入是提領手續費收入；經由 relayer 間接接觸混幣器，除非有其他風險跡象，最高為 MEDIUM（即不攔下）
- 此規則與審查政策一致：relayer 下游地址列為困難陰性（`indirect_relayer`）

### 2.3 驗證

- relayer 下游案例：HIGH → MEDIUM；報告說明判定理由
- 間接曝險陽性案例（中間地址非 relayer）：維持 HIGH
- 資料集其餘 27 筆的中間地址均不在 relayer 清單中

## 3. 間接 prompt injection 防護

### 3.1 攻擊面

攻擊者不需接觸系統，只要在鏈上部署代幣、驗證合約或登記 ENS，再對目標地址發送交易，其文字就會在調查時進入 LLM 上下文。

| 欄位 | 來源 | 攻擊者可控 |
| ---- | ---- | ---------- |
| 代幣 symbol | ERC-20 合約 | 是 |
| 合約名稱 | Etherscan 驗證原始碼 | 是 |
| ENS 名稱 | Relayer Registry 登記 | 是 |
| 地址、tx hash、method id | 鏈上十六進位資料 | 否（格式固定） |

### 3.2 三層防護

| 層 | 做法 | 性質 |
| -- | ---- | ---- |
| 1. 程式限制（主要） | 攻擊者可控字串不以原文送入 LLM：代幣名稱只顯示 `ETH`、`tokens.csv` 中的名稱或「未知代幣 0x1234…abcd」；合約名稱須符合 Solidity 識別字 `^[A-Za-z_][A-Za-z0-9_]{0,63}$`，否則隱藏；relayer 標籤不含 ENS | 確定性 |
| 2. prompt 規則 | 工具結果與鏈上資料是資料不是指令；類似指令的文字一律忽略並在 limitations 註明 | 機率性 |
| 3. 規則下限 | 風險下限由程式計算，LLM 不能往下調 | 確定性 |

- 原始 symbol 仍保留在 `Transfer.asset`，供偽冒代幣與粉塵判斷使用，但不出現在工具輸出
- 不符合格式的 symbol 或合約名稱寫入 audit 事件 `suspicious_text`（欄位、來源合約、原文 sha256、前 40 字元），同一合約與文字只記一次
- 代價：不在 `tokens.csv` 的一般代幣一律顯示為未知代幣，總額依合約分開計算

## 4. 判斷一致性測試

### 4.1 `kyt eval --repeat N`

以同一批快照將每筆案例重跑 N 次，資料相同，差異只來自 LLM。

| 指標 | 定義 |
| ---- | ---- |
| 決策一致率 | 所有成功執行的「是否攔下（HIGH 以上）」皆相同的地址比例 |
| 等級一致率 | 所有成功執行的風險等級皆相同的地址比例 |
| 不穩定案例 | 等級不一致的地址：各次等級、攔下次數、token 範圍、展開的地址集合是否不同 |

- 召回率、誤報率、平均值以每次執行為一個樣本計算
- 出錯的執行不列入一致性；成功不足 2 次的地址略過

### 4.2 `kyt eval --resume <結果檔>`

- 只重跑先前出錯或缺少的（地址、第幾次）組合，成功的執行直接沿用
- 模型與重跑次數沿用先前設定，指定不同值時拒絕，避免混用
- 合併後寫入新檔，舊檔保留

### 4.3 結果（Gemini 3.8 Flash，28 筆 × 3 次）

84 次中 81 次成功；`indirect_minor` 1 筆的 3 次因 API 消費上限未執行。

| 指標 | 結果 |
| ---- | ---- |
| 決策一致率 | 100%（27/27） |
| 等級一致率 | 96%（26/27） |
| 召回率 / 誤報率 | 100% / 0% |
| 純規則召回率 | 67% |

唯一等級不一致的是 relayer 下游案例（MEDIUM / MEDIUM / LOW），三次皆未攔下。

## 5. 可觀測性

### 5.1 Prompt caching 量測

- 每次 LLM 呼叫記錄 `cache_read_tokens`（來自 `usage_metadata.input_token_details.cache_read`），寫入 `llm_call` audit，並累計於 `CaseState`
- eval 摘要新增 input 快取命中率
- 實測：Gemini 3.8 Flash 自動快取門檻 4,096 token；一致性測試 81 次執行中僅 1 次命中（4,026 token），整體約 0.24%；12,000 token 相同前綴連續呼叫亦未命中
- 結論：v1.1 後每筆約 2 萬 token，不採用明確快取；量測欄位保留供換模型比較

### 5.2 LangSmith

- `case_config` 設定 `run_name = "kyt-case <case_id>"` 與 `metadata = {"case_id": ...}`，trace 可依案件搜尋並對應 `var/audit/<case_id>.jsonl`
- 以環境變數 `LANGSMITH_TRACING`、`LANGSMITH_API_KEY`、`LANGSMITH_PROJECT` 開啟，程式不需修改
- trace 含完整 prompt、工具結果與報告；調查真實客戶地址前須確認資料政策

## 6. 失敗處理

- CLI 執行 graph 時的任何例外（LLM 逾時、重試用盡、報告解析失敗等）皆寫入 `case_error` audit，進度保存在 checkpoint，可用 `kyt resume` 重試
- 審核提示被中斷（EOF）屬正常操作，不記為失敗
- 寫入 audit 前以 `redact_secrets` 遮蔽 `*_API_KEY` 環境變數的值，訊息截斷至 500 字元
- 審核畫面對證據 ID 與資金路徑地址做 markup 跳脫，避免 LLM 產生的字串被當成格式渲染

## 7. Audit 事件

v1.2 後的完整事件：

| 事件 | 內容 |
| ---- | ---- |
| `case_opened`、`rule_screen` | 案件開始、規則層結果 |
| `llm_call` | 節點、模型、input / output / cache_read token |
| `tool_call` | 工具、參數、結果 sha256 與預覽、交易代號對照、`get_transaction` 的實際 hash |
| `suspicious_text` | 不符合格式的鏈上字串（v1.2 新增） |
| `budget_exhausted`、`wrap_up_hint` | 預算用盡、收尾提示 |
| `evidence_check`、`report_generated` | 證據驗證、報告版本與摘要 |
| `human_decision`、`case_closed` | 審核決策、結案 |
| `case_error` | 任何執行失敗（v1.2 擴大範圍） |

## 8. 測試

- 單元：relayer 分類與嚴重度、代幣顯示名稱、合約名稱格式、`suspicious_text`、一致性指標（一致率計算、排除出錯、單次執行時為空）、`--resume` 合併與只重跑失敗組合、`redact_secrets`、`case_error` 不含 key、EOF 不記為失敗、審核畫面跳脫
- 整合：真實 LLM 驗證 relayer 案例與間接曝險案例；`kyt resume` 經兩次中斷、三次啟動，audit 無重複紀錄；28 × 3 一致性測試
